## PDF engine findings

Direct use of ordinary pdf-lib font embedding did not provide the required Thai mapping/placement pipeline. Fontkit's glyph code-point metadata can be shared/mutated during Thai sara-am decomposition, so a per-glyph mapping initially produced duplicated or missing characters for `กำ น้ำ ทำ น้ำ สมชาย`.

The selected adapter shapes each grapheme with Fontkit, builds a document-specific OpenType font with OpenType.js, and assigns the exact original Unicode grapheme to the PDF CID. Glyph paths exist inside the embedded font, as in ordinary outline fonts; page content is PDF text, not paths or raster images. No invisible replacement-text layer or filtering of copied characters is used. Derived fonts use the name `SabuyText` and embed OFL/copyright metadata.

Review found and fixed: font resource collision on re-export; raw CropBox mismatch against PDF.js visible intersection; later-page dimension validation. Each has a regression test.

## Synthetic performance probe

Command: `node --import tsx scripts/pdf-probe.mts`.

Environment: Node 24.15.0, macOS arm64. Synthetic vector forms with one added three-line Thai/English block. Observed preliminary export times: 1 page 34 ms, 20 pages 19 ms, 100 pages 23 ms. These are single-run observations including warmup differences, not a benchmark promise or browser memory measurement. Reproduce to obtain timings for the current machine/build.

25 MB / 100 pages are conservative input guardrails. The main page canvas is capped at 16 million pixels by lowering render resolution. Large scanned-image PDFs still need representative performance testing.

## Remaining manual release checks

- Adobe Acrobat and Safari/macOS PDF viewer: visual text, find, copy, font portability, and accessibility behavior. PDF.js extraction and Chromium preview were tested; other viewer results are not claimed.
- Representative scanned PDFs, unusual color spaces, mixed page sizes, and long real-world Thai text.
- Browser memory profiling and time budgets on lower-powered desktop machines.
- Broader security review and dependency update policy before public production deployment.

The editor supports a defined Thai/English/Sarabun subset, explicit newlines, desktop interaction, and no persistent drafts. It intentionally does not implement old-text editing, automatic Thai line breaking, cloud storage, accounts, billing or mobile PDF editing. QR signature capture was subsequently added; see [signature verification](2026-09-21-signatures.md).

## Static deployment regression

The first Release browser run detected an un-fingerprinted Blazor loader URL returning HTML. Fixed index markup to use the .NET 10 fingerprint placeholder and publish-generated import map. Docker computes the exact import-map SHA-256 CSP hash; it does not permit arbitrary inline scripts. CI now runs browser tests against both the development host and Docker Release image.
